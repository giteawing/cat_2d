# AGENTS.md — руководство для агентов и разработчиков

Cat Portal Adventure 2D — пазл-платформер на чистом HTML5/JavaScript (Canvas 2D, собственная физика, без сборщика и
без зависимостей в рантайме). Этот файл — карта проекта: где что лежит, как проверять изменения, что сейчас в работе
и на какие грабли уже наступали.

Русский — язык всего игрового текста (таблички, HUD, названия уровней). Комментарии в коде и документация тестов — на английском.

---

## 1. Быстрый старт

```bash
npm start                 # статический сервер на 0.0.0.0:8080 → открыть в браузере
cd tools && npm install   # один раз: @napi-rs/canvas для headless-тестов (node_modules могут пропасть — переустановить)
cd .. && npm test         # ~150 быстрых проверок (физика, порталы, оружие, барьеры, лазеры, преломление, sanity уровней)
npm run walk              # полные прохождения всех 12 уровней ботом (~11 минут)
node tools/walkthroughs/level12.mjs   # прохождение одного уровня (idx = номер файла)
npm run shots             # скриншоты всех уровней в tools/out/ (в .gitignore)
```

Подробнее — `HOW_TO_RUN.md` (RU) и `README.md` (EN, список уровней и механик).

**Git:** ветка `arena/01a06ff3-cat-2d`, remote `origin` = GitHub `giteawing/cat_2d`. Коммитить и пушить после каждой
значимой подзадачи: `git add -A && git commit -m ... && git push origin arena/01a06ff3-cat-2d`.
Если локальный `.git` «сбросился» — `git fetch origin arena/01a06ff3-cat-2d && git reset -q --soft FETCH_HEAD`
(файлы на диске остаются источником истины). Никогда не откатывать файлы через `git checkout <file>`.

## 3. Частые задачи — где править

| Что нужно | Где |
|---|---|
| **Внешний вид кота** (цвета, пропорции, глаза, хвост) | `src/characters/cat/catSprite.js`: палитра `CAT` (строка ~8), геометрия в `drawCatLocal`/`drawHead`/`drawTail`. Позы/анимации — `computePose`. Проверить: `node tools/catsheet.mjs` → `tools/out/catsheet.png` |
| **Пушки в лапах** | `src/weapons/gunSprites.js` (`drawGun`), цвета `GUN_COLORS` |
| **Тексты подсказок на уровне** (таблички «?») | в `setup()` уровня: `k.sign(tx, ty, 'текст')`, заголовок комнаты — `k.message(tx, ty, w, h, 'Заголовок', 'подзаголовок')` |
| **Всплывающие подсказки HUD** (оружие, барьеры, туннелирование) | `src/core/game.js` — поиск по `hud.show(` |
| **Стартовый экран** (название, слоган, список управления) | `src/core/game.js` → `renderTitle()`; экран выбора уровня — `renderSelect()`; итоги мира — `renderWorldDone()` |
| **Название/подзаголовок уровня** | поля `name`, `subtitle` в объекте уровня |
| **Новый уровень** | скопировать `src/levels/world02/level04.js`, добавить в `src/levels/index.js`, написать `tools/walkthroughs/levelNN.mjs`, обновить README/HOW_TO_RUN |
| **Новый предмет** | `PROPS` + `drawProp` в `src/physics/props.js` |
| **Новый пазл-компонент** | класс в `src/puzzles/puzzles.js` с `update(dt, game)` и `draw(ctx, time)` (+ `drawOverlay` если рисуется поверх кота), фабрика в `levelKit.js`, юнит-тест в `tools/test.mjs` |
| **Тема оформления** | `THEMES` в `src/render/tileRenderer.js`, поле `theme` уровня |
| **Звуки** | `src/audio/audio.js` → `play()`; вызывать через `game.sfx('name')` |
| **Управление** | `src/core/input.js` (коды клавиш) + `src/characters/cat/player.js` |

Терминология в игровом тексте: тайл `~` называется **«потенциальный барьер»** (не «электрополе»). В коде идентификаторы
остались `EFIELD`/`isField`/`FieldGate`/`onField` — это нормально.

## 4. Уровни и механики

- Мир 1 (house/lab): 1 ходьба и подарки → 2 гравипушка → 3 портальная пушка → 4 плиты/двери → 5 лифты/one-way →
  6 вентиляторы/разбиваемые → 7 потенциальные барьеры + квантовое туннелирование (Q) → 8 отключаемые барьеры (FieldGate).
- Мир 2 (observatory): 9 лазеры/зеркала/приёмники → 10 порталы для луча → 11 зеркала на лифтах → 12 «Купол»: всё вместе
  + финал с **преломлением** (`k.medium`, n = 1.5, закон Снеллиуса; наклонный лазер `k.laser(tx, ty, 50)` — угол в градусах).
- Мир 3 (aquarium, В РАБОТЕ): 13 «Аквариум» — **вода** (`k.water(tx,ty,w,h,{level, levelEmpty, requires, speed})`):
  плавучесть по `body.density` (PROPS: material → DENSITY в props.js; кот 0.55), сопротивление, плавание (player.js
  «swimming»), анимации swim/float, брызги (`world.onSplash`), вентиль наполняет бак и поднимает всё плавучее. Вода —
  ещё и оптическая среда (n = 1.33). Планируемые уровни 3-2…3-4: шлюзы (два бака и переливы), подводные порталы
  (портал под водой выбрасывает струю), тонущие/всплывающие платформы-плоты с грузом.
- Правила механик, которые нужно помнить при дизайне уровней:
  - порталы ставятся только на кирпич `#`; стекло `G` блокирует выстрел, решётка `|`, one-way `=` и барьер `~` — нет.
  - лучи и выстрелы порталов проходят сквозь барьер, предметы и кот — нет (кот в квантовом режиме с разбега: 25 %).
  - горизонтальный луч в ряду R идёт на y = (R+0.5)·32; предмет на полу F занимает ряд F−1.
  - приёмник `latch: true` (по умолчанию) запоминает свет; `latch: false` — «замок» (дверь открыта, пока приёмник тёмный).
  - FieldGate не замыкается, пока в проёме кто-то стоит; тело, оказавшееся ВНУТРИ барьера, получает свободный выход.
  - Портал в полу на пути кота проглотит его — не оставлять напольные порталы на маршруте.
  - Лифт с местом посадки: стоячий прыжок ≈ 3.3 тайла, с разбега ≈ 5.6; лифт, отдыхающий на 3 тайлах, нужна ступенька.
  - Смена оружия РОНЯЕТ удерживаемый предмет; удерживаемое зеркало тоже отражает луч.

## 5. Как проверять изменения

1. `npm test` — обязательно после любой правки физики/пазлов/уровней (падает при первом сломанном уровне sanity).
2. Прохождение затронутого уровня: `timeout 600 node tools/walkthroughs/levelNN.mjs > /tmp/l.log 2>&1; grep -vE "^\s+at " /tmp/l.log`.
   Ожидаемо: `RESULT level N: state=complete gifts=5/5 fails=0 → PASS`.
3. Перед пушем крупных изменений — `npm run walk` (все 13).
4. Визуальная проверка — `Driver.shot('name')` → `tools/out/name.png`, затем просмотреть картинку.
5. Отладка сцен — маленький скрипт в /tmp, который телепортирует кота: `b.x = tx*32-15; b.y = ty*32-54` (ty — ряд пола).
   Точка спавна должна быть в пустых тайлах.

Ограничения харнесса: вид 24×13.5 тайла, `aimClick` бросает «aim target off-screen», для потолка используй
`peekAimClick('KeyW', …)`; `walkTo` в закрытую дверь виснет — сначала убедись, что канал открыт; циклы ожидания
ограничивай (`≤1500` кадров).

## 7. Известные проблемы и ограничения

- Референс-картинка кота отсутствует в репозитории; вид кота собран по описанию `assets/reference/CAT_REFERENCE.md`.
- Захват гравипушкой рядом с кучей предметов может выбрать не тот предмет (луч захвата берёт ближайший).
- Идущий кот толкает напольные предметы — не прокладывать маршрут через припаркованный ящик/зеркало.
- Туннелирование случайно (25 %): в прохождениях боты повторяют разбег в цикле; игроку это объяснено табличками.
- Лазер обновляется до перемещения зеркал в этом же кадре (puzzles.update → updateMirrors): при быстром движении
  зеркала возможна задержка в один кадр — визуально незаметно.
- Наклонные лучи (`Medium`, угловые лазеры) пересекают порталы «в лоб» с округлением направления — при нужде
  наклонного луча сквозь портал проверить визуально.
- Нет автотестов на звук/HUD-верстку; проверяется скриншотами.

## 8. Рекомендации по оптимизации (если появится нужда)

Текущая стоимость кадра в headless-профиле (`/tmp`-скрипт с обёртками таймеров вокруг `render*`): ~2–3 мс на самых
больших уровнях, из них рендер ≈ 80 %. Уже сделано:
- **Тайлы** кэшируются в offscreen canvas; FieldGate/разбитие стены перерисовывают только затронутые клетки
  (`TileRenderer.updateCells`, 0.07 мс вместо 26 мс на карту 150×36).
- **Фон**: узор обоев — `CanvasPattern`, а не сотни дуг за кадр.
- **HUD**: перенос строк подсказки (`measureText`) кэшируется по строке.
- **Лазеры**: список сред/приёмников/дверей/тел собирается один раз за физический шаг (`game._optics`, ключ `game.frameId`).
- **Отсечение по камере** для декора, табличек, подарков и предметов (`inView` в `renderWorld`).

Если понадобится ещё:
- **Физика**: `World.step` — сортировка + узкие пары; при > 200 тел добавить sleeping для тел в покое
  (уже есть `wake()`, нет флага sleep) или простую сетку.
- **Частицы** (`effects.js`) — фиксированный пул вместо push/filter.
- HUD-панели с `shadowBlur` (индикатор квантового режима) — самая дорогая часть HUD; можно кэшировать в offscreen.
- Держать все тексты/цвета в верхних константах модулей — это уже правило проекта, продолжать его.
